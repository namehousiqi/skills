# Step-by-Step Mode

## Activation Gate

仅在用户当前请求明确包含“`一步步做`”或不区分大小写的“`step by step`”时启用本模式。

- 不从任务规模、功能点数量、“拆分任务”“分阶段”或其他近义表达推断启用。
- 模式一旦启用，在全部步骤完成或用户明确退出前持续有效；后续回复“继续”时不要求重复触发词。
- 用户明确说“不用一步步”“直接做完”或等价指令时退出本模式，恢复普通流程。
- 用户已经明确授权开始第一步时直接开始；否则先展示拆分结果并等待确认。

## Build the Step Plan

1. 盘点功能点、依赖、未知项、共享风险和验收条件。
2. 按依赖顺序拆成可独立交付和验证的步骤；不要按文件机械拆分。
3. 为每一步写清目标、范围、预期行为、验证方式和前置依赖。
4. 展示编号清单，并将状态限制为 `pending`、`in_progress`、`completed`；同时最多一个步骤为 `in_progress`。
5. 优先安排能消除关键不确定性或建立测试基线的步骤。

## Execute One Step at a Time

1. 每次只实施用户已确认的当前步骤，不提前夹带后续步骤。
2. 为当前步骤读取所需的对应流程文档；不要一次加载所有 references。
3. 完成最相关的检查或测试后，报告本步改动、验证结果、风险和对后续步骤的影响。
4. 更新步骤状态，然后明确询问用户是否继续下一步。用户回复“继续”时只推进一个步骤。
5. 新发现改变剩余计划时，说明证据并重新列出尚未完成的步骤，等待用户确认后再继续。
6. 除非用户明确要求，不要为每一步 commit 或 push。

## Completion

最后一步完成后执行一次跨步骤回归检查，确认组合行为、兼容性和文档一致性，再给出完整交付总结。
