# Git

## Git Delivery

1. 拉取、合并或提交前检查工作区、分支、上游和远端差异；保留无关用户改动。
2. 按用户指定的业务优先级处理冲突；复杂、语义冲突或无法判断的冲突先暂停询问。
3. 提交前检查 diff、敏感信息、`git diff --check` 和相关测试。
4. 只有用户明确要求时才 commit、push 或改变远端分支。
5. 操作完成后简要报告分支、提交、合并或推送结果以及未处理状态；同时完成了功能或 Bug 时，按主文档加载的交付总结规范说明行为变化。

## Commit Message

1. 创建提交前先查看近期提交主题，遵循当前仓库已有的语言、格式和前缀约定。
2. 仓库没有更明确约定时，提交说明优先使用中文，并复用 `[add]`（新增功能）、`[update]`（完善或变更）、`[fix]`（缺陷修复）等现有前缀。
3. 使用“`[前缀] 中文简述`”格式，例如：`[add] 完成技能商店 V2 功能与验收覆盖`。
4. 只暂存本次任务相关文件，不把无关修改带入提交。
5. 除非用户明确要求，不要仅为改写提交说明而 amend 已有提交；执行 amend 时确认提交内容的 tree 未发生意外变化。
