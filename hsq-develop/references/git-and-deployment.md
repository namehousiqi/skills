# Git and Deployment

## Git Delivery

1. 拉取、合并或提交前检查工作区、分支、上游和远端差异；保留无关用户改动。
2. 按用户指定的业务优先级处理冲突；复杂、语义冲突或无法判断的冲突先暂停询问。
3. 提交前检查 diff、敏感信息、`git diff --check` 和相关测试。
4. 只有用户明确要求时才 commit、push 或改变远端分支。
5. 交付总结包含目标、关键文件、行为变化、验证结果、配置/部署注意事项、兼容性和剩余风险。

## Deployment Diagnosis

1. 先只读收集客户、容器或 K8s 的版本、镜像、env、挂载、权限、网络、探针、日志和资源限制，并与成功环境对比。
2. 区分应用代码、配置缺失、镜像/运行时差异、存储权限、网络依赖和数据问题；建立最小复现后再修改。
3. 默认不重启生产服务、不删除数据、不改远端配置、不发送业务写请求。需要操作时先说明目标、影响和回滚方式并获得授权。
